Computación Paralela · Tema 4

Diseño de aplicaciones paralelas

La metodología PCAM en cuatro etapas: del problema secuencial al programa paralelo. Cada etapa, sus alternativas de diseño y ejemplos.

P · Particionado C · Comunicación A · Aglomeración M · Mapeo
P
Particionado / Descomposición
Exponer el paralelismo

Romper el problema en el mayor número de tareas pequeñas (grano fino). Objetivo: máxima flexibilidad para las etapas siguientes. Buscar al menos un orden de magnitud más de tareas que procesadores.

Tipo

Descomposición de dominio

Se dividen los datos. Cada tarea hace el mismo trabajo sobre su trozo de datos. Primero se reparten los datos, luego se asocia el cómputo.

Ejemplo · Simulador de climaA cada tarea se le asigna una porción del mapa a simular; las celdas vecinas intercambian su estado en la frontera.
Tipo

Descomposición funcional

Se divide el cómputo. Cada tarea es un trabajo de naturaleza distinta. Útil cuando el sistema tiene componentes cualitativamente diferentes.

Ejemplo · Simulador de climaComponentes separados: atmósfera, océano, hielo, hidrología, CO₂. Cada uno luego se paraleliza por dominio (anidamiento).
Técnicas de descomposición

Cinco enfoques útiles

No hay receta única; estas técnicas ayudan según el problema:

  • Recursiva — divide y vencerás: el problema se parte y cada subproblema se descompone igual.
  • De datos — particionar la estructura de datos principal (la forma más común).
  • Exploratoria — explorar un espacio de búsqueda repartiendo las ramas (ej. criba por un primo Pᵢ).
  • Especulativa — ejecutar tareas por adelantado antes de saber si harán falta.
  • Híbrida — combinar varias de las anteriores.

Verificación del particionado

  • ¿Define al menos 10× más tareas que procesadores? (si no → poca flexibilidad)
  • ¿Evita cálculos y almacenamiento redundantes? (si no → poco escalable)
  • ¿Todas las tareas tienen tamaño similar? (si no → difícil balancear)
  • ¿El nº de tareas crece con el tamaño del problema, no su tamaño individual?
  • ¿Has considerado alternativas (dominio y funcional)?
C
Comunicación / Organización
Definir el flujo de datos

Determinar qué información intercambian las tareas y el ámbito de esa comunicación. Si no hay dependencias → problema "embarazosamente paralelo" (sin comunicación).

Ámbito

Comunicación local

Una tarea necesita datos de pocas tareas vecinas. Patrón claro → se dibujan los canales que ilustran el flujo.

EjemploStencil sobre una malla: cada celda usa solo a sus vecinas inmediatas.
Ámbito

Comunicación global

Muchas tareas aportan datos a un cálculo común (suma, máximo, difusión). No se dibujan canales aún: se anota como operación colectiva.

EjemploReducir el mejor valor entre todos los procesos (la "mejor cota" en Branch & Bound).
Tipo

Síncrona (bloqueante)

Las tareas se bloquean esperando a que la comunicación se complete. Más simple, pero introduce esperas.

Tipo

Asíncrona (no bloqueante)

Permite transferir mientras se sigue calculando → solapa cómputo y comunicación. Mejor rendimiento, más compleja.

A tener en cuenta

Coste y solapamiento

  • Coste = latencia (coste fijo por mensaje) + ancho de banda (coste por dato). Agrupar mensajes amortiza la latencia.
  • Localidad — comunicar con vecinos cercanos es más barato que con tareas lejanas.
  • Pipeline — encadenar etapas permite solapar cómputo y comunicación, como el pipeline de instrucciones del procesador.
  • Equilibrio — operaciones de comunicación desequilibradas sugieren una mala descomposición.
A
Aglomeración / Agrupación
Ajustar la granularidad

Combinar tareas finas en tareas mayores para reducir comunicación y el coste de crear tareas. Conflicto a equilibrar: flexibilidad (grano fino) frente a eficiencia (grano grueso).

Granularidad

Fina vs gruesa

Grano fino: muchas tareas pequeñas → flexible pero mucha sobrecarga de comunicación. Grano grueso: pocas tareas grandes → eficiente pero menos flexible. La aglomeración sube la granularidad.

Principio clave

Efecto superficie-volumen

El cómputo crece con el volumen del subdominio; la comunicación, con su superficie. Aglomerar en todas las dimensiones reduce la superficie para un mismo volumen → menos comunicación relativa.

Formas de agrupar (dominio)

¿Cómo reparto los datos entre las N tareas?

Por bloques

N trozos contiguos, 1 por tarea. Maximiza la localidad (vecinos juntos, poca comunicación). Ideal con carga uniforme.

Cíclico

Datos repartidos intercalados (como repartir cartas). Mejora el balanceo si la carga es desigual, a costa de localidad.

bloque-cíclico = punto medio 1D · vector 2D · matriz (filas/columnas/cuadros) 3D · volumen
M
Mapeo / Asignación
Asignar procesos a procesadores

Minimizar el tiempo de ejecución equilibrando carga y maximizando localidad. Es un problema NP-completo: se usan heurísticas.

Patrones de estructura

Cómo se organiza el programa

SPMD

Mismo programa, datos distintos. El más usado; base de MPI. El ID del proceso diferencia el comportamiento.

Master / Worker

El maestro reparte tareas, los workers procesan. Con Pool de trabajo para balanceo dinámico. Ideal: embarazosamente paralelos.

Pipeline

Etapas encadenadas; la salida de una alimenta la siguiente. Grano fino. Ej: criba de Eratóstenes (cada Pᵢ criba por un primo).

Balanceo de carga · Estático

Reparto fijo, decidido antes

Se asigna de antemano y no cambia. Sirve cuando la carga se conoce o es estable.

  • Asignación proporcional — reparte según la capacidad de cada proceso (sistemas heterogéneos).
  • Bisección recursiva — corta en mitades de igual carga, recursivamente. Para dominios irregulares con localidad.
  • Algoritmos locales — ajustan usando solo información de vecinos.
  • Probabilísticos (aleatorios) — asignar al azar; simple, equilibra estadísticamente con muchas tareas.
  • Cíclica (Round-Robin) — repartir en orden 1,2…P y volver a empezar. Bueno con tareas uniformes.
Balanceo de carga · Dinámico

Reparto que se ajusta en ejecución

Cuando la carga cambia o es impredecible. Se reequilibra durante la ejecución.

  • Centralizado — cola de tareas en el maestro; el worker pide otra al terminar. Auto-planificación: se reparten grupos de tamaño K (K grande → menos accesos, peor balanceo; K pequeño → mejor balanceo, más contención).
  • Distribuido — los procesos intercambian tareas directamente: iniciado por el receptor (pide cuando va vacío), por el remitente (cede cuando va sobrecargado), o híbrido.
GuíaPreferir estático (1 tarea → 1 procesador). Si la carga varía, pasar a dinámico o reformular.
